## Missing days, credits exhaustion and branch discovery

- **A day without a report is NOT evidence that an agent ran, that it failed to run, or that a research route is exhausted.** Mark its stage `PENDING / NO_VERIFIED_REPORT`. Quota or credits exhaustion may explain gaps but must not be asserted without actual run evidence. A missing yesterday does not truncate the search.
- **No arbitrary 2-day, 7-day, 30-day or other calendar limit.** Prefer enumerating actually existing dated folders over trying one API request per elapsed day. If a listing is paginated or incomplete, follow the available pagination/tree/commit-history route or explicitly disclose incomplete coverage; do not silently claim the returned last folder is globally latest.
- **Do not select by folder date alone.** Within a day, append-only sections may contain multiple actual invocations, partial checkpoints, later corrections and immutable publication receipts. Identify the latest real publication evidence and preserve corrections/refutations. Later publish time may differ from scheduled trigger time; record both where available.
- **Use hashes as provenance, not as a substitute for reading.** A source SHA or last-run pointer alone does not transmit mathematical reasoning. Retrieve the necessary report section and full original derivation when the current session does not actually contain it; reuse unchanged proof evidence without repeating expensive builds.
- **No work on stale instructions.** Compare current live main against the remembered policy and review subsequent research changes; a stale report is a starting state, never superior to later merged mathematics or current user priorities.
