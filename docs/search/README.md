# Static search corpus (for agents that can read files but not run code)

Everything in this directory except this README is generated by [`scripts/search_catalog.py`](../../scripts/search_catalog.py) from tracked sources, [coordinate-atlas.json](../coordinate-atlas.json) and [proof-obligations.json](../proof-obligations.json). Each file stays far below GitHub code search's 384 KB per-file limit, so connector-based code search indexes it, and every topic page is small enough to fetch on its own. Tags are lexical search hints, not mathematical claims; open the cited source before relying on anything.

## Where to start

1. **[INDEX.md](INDEX.md)** lists one page per coordinate (`coordinates/<ID>.md`) and per route (`routes/<ROUTE>.md`), with tagged-file counts.
2. **A coordinate page** gives the definition, notation, search aliases, typed crosswalks to other coordinates, every proved rewrite of its Lean definitions, and the 30 files that use it under any name. Example: [the CORR-4 remainder](coordinates/COORD-CORR4-REMAINDER.md) lists 12 Lean theorems that rewrite `lowOwnerPhysicalAmplitudeRemainder` in different coordinates across 8 files.
3. **A route page** lists the most relevant files for one of the ten RH routes.
4. **The [coordinate atlas](../COORDINATE_ATLAS.md)** explains how the coordinates fit together, which letters collide (`D`, `C`, `E`, `K`, `Q`, …) and which normalization traps exist.

## Machine-readable shards

| File pattern | One line per | Fields |
| --- | --- | --- |
| `catalog-<shard>.jsonl` (`research-lean-vf`, `research-lean`, `research-notes`, `library-proof`, `library-core`, `docs`, `code`) | tracked `.lean`, `.md`, `.py`, `.cpp`, `.c`, `.tex` file | `path`, `kind`, `title`, `date`, `prs`, `coordinates` (atlas IDs, best first), `routes`, `proof_nodes` (registry IDs mentioned), `lean` (theorem/definition counts, headline definitions), `status_words` (status tokens present in Markdown) |
| `rewrite-families-<range>.jsonl` (`a-k`, `l`, `m-r`, `s`, `t-z` by first letter) | Lean definition with at least one proved rewrite | `definition`, `defined_in`, `rewrites` (file → theorem names `<def>_eq_…` / `<def>_iff_…`) |
| `MANIFEST.json` | — | schema, record counts, input fingerprint |

With code search (for example the GitHub connector), search inside these shards for an atlas ID (`COORD-FINITE-AC`), a registry ID (`OPEN-CORR4-RELAXED-REMAINDER`) or a Lean definition name, and you get every file or rewrite family that mentions it. Without search, open the matching topic page instead.

## Freshness

The corpus is regenerated with `python3 scripts/search_catalog.py --write`; `--check` reports staleness (CI prints a warning rather than failing, so unrelated research PRs are never blocked). Because new research lands daily, treat counts and rankings as approximate. Lean statements, proof status and PR state must come from the source files, [the proof-dependency DAG](../PROOF_DEPENDENCY_DAG.md) and GitHub.
