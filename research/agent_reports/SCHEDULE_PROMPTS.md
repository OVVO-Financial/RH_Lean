## Practical caveats

1. The user reports that all seven Agent Studio GitHub connections have read/write access except delete; this capability must still be verified on each actual run. The repo's `main:AGENTS.md` limits six research agents to own dated reports and, once reviewed and merged, gives Agent #7 the additional restricted proof-PR lane. Broad credentials do not remove policy restrictions.
2. GitHub repository write credentials are not necessarily restricted by a prompt to a folder/branch. Prefer server-enforced least privilege when available. Otherwise ask for explicit approval of the operational risk or use a posting intermediary that enforces allowed paths.
3. Multiple simultaneous writers to one branch can create Contents API conflicts. The staggered times reduce but do not eliminate them; re-fetch, reconcile, retry once.
4. Scheduling is asynchronous, not a dependency engine; two runs per day do not guarantee two completed handoffs. A second invocation must **append** to the same date's stage file, consult the latest completed upstream timestamp, and never invent missing reports. Preserve run IDs and SHAs.
5. New findings that matter to the formal RH proof move through ordinary reviewed code PRs. A research report is not equivalent to a proved Lean theorem.
